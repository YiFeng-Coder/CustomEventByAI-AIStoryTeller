# P4 交付说明（动作库扩展 v2）

版本：**0.6.0**（0.5.0 → 0.6.0）
范围：B0 地基 + B1 心理与关系 + B2 场景与破坏 + B3 交互与呈现。
**B4（世界层）不做**；**pick_cell / pick_pawn 不做**（按你的要求）。

一句话：动作 26 → 42，新增"人心 / 现场 / 交互"三组；顺带补上了坐标、目标、回执三处老缺口。

## 2. 三处按实际情况调整的地方（不是偷工减料，是 1.7 的 API 变了）

| 项 | 计划 | 实际 | 原因 |
|---|---|---|---|
| `story.focus` 的音效 | spot + soundDef | **只有镜头** | 1.7 的 `SoundDef` / `SoundRoot` / `SoundStarter` 都没有公开的"播放一次"入口（逐个编译验证过），硬做要反射私有字段 |
| `story.objective` 的常驻提醒 | 右侧 Alert | **信件 + 每日消息提醒** | `AlertsReadout` 没有公开注册入口（Register / AllAlerts / TryRegister 全部不存在），只能反射私有字段——比每日一条消息更容易炸 |
| `story.choice_letter` | 原版 ChoiceLetter | **已实现**，选项进信件栏，选中回传 `choice_selected` | 子类化 `ChoiceLetter` 可行（只需实现 `Choices`），已做 Scribe，读档后仍能选 |

## 3. 顺手修掉的一个老 bug

旧版本里，**同一阶段"先生成、后引用"是必定失败的**：

`~lua
actions[#actions+1] = { opId="a1", type="pawn.spawn", args={ pawnKind="Villager", handle="p1" } }
actions[#actions+1] = { opId="a2", type="pawn.hurt",  args={ handle="p1", hediffDef="Cut" } }  -- 旧版必被拒
`~

原因：`ValidateAll` 在**执行之前**跑，此时句柄还没登记。动作库参考里的示例其实一直是错的。

现在：校验阶段把"本阶段 spawn 类动作声明要生成的句柄"当作 pending 放行，
执行阶段严格解析（`ActionContext.Validating` 控制）。如果脚本把引用写在生成之前，
执行到时仍然解析失败——但那属于脚本顺序错误，不是校验器的问题。

## 4. 提示词预算（实测 + 估算）

| 项 | 0.5.0（26 个） | 0.6.0 常驻（23 个） | 0.6.0 + 1 组关键词 | 0.6.0 全量（42 个，不裁剪） |
|---|---|---|---|---|
| 动作手册 | 2101 字 | 1920 字 | 约 2450 字 | **3437 字**（实测） |
| Def 名单 | 约 1900 字 | 约 1500 字 | 约 2100 字 | 约 3300 字 |
| 固定部分（Core+Rules+user） | 约 3570 字 | 3570 字 | 3570 字 | 3570 字 |
| **单次合计（约）** | **7.6k** | **7.0k** | **8.2k** | **10.3k** |

- 常驻 = 叙事 + 生成 + 地图 + 角色（23 个）；
- 心理 / 场景 / 交互 / 世界按剧情关键词出现，最多再加两组；
- 关键词命中两组时最坏约 **9.5k**，仍低于"不裁剪就加 16 个动作"的 10.3k；
- 玩家在设置里关掉某组，该组连关键词都不会触发。

> 剧情关键词裁剪只影响提示词。玩家在设置里关闭动作组后，该组动作也会被运行时校验拒绝。

## 5. 设置里新增的四项

| 设置 | 默认 | 作用 |
|---|---|---|
| 心理与关系（想法 / 心情 / 灵感 / 特质 / 关系 / 崩溃） | 开 | 关闭后禁用这一组动作 |
| **允许心理层影响你的殖民者** | **关** | 关：想法 / 心情 / 关系只作用于 AI 生成的角色；开：可以落到你的殖民者身上（危险动作永远不行） |
| 场景与破坏（建筑 / 地形 / 屋顶 / 污渍 / 动物 / 清除 / 塌方） | 开 | 关闭后禁用这一组动作 |
| 交互与呈现（叙事目标 / 镜头 / 信件抉择） | 开 | 关闭后禁用这一组动作 |

设置页在「叙事风格提示词」下面新增了「动作库」一节；"恢复默认参数"会一并恢复。

## 6. 怎么验收（不用花 API 钱）

1. 进游戏，设置页确认「动作库」四项都在；
2. 调试窗点 **注入 P4 演示**：会一次性跑
   信件 → 镜头 → 血迹 → 建筑 → 地形 → 兽群 → 两个角色 → 心情 / 想法 / 灵感 / 特质 / 关系
   → 清除 → 叙事目标 → **信件栏里的抉择**；
3. 打开信件栏里的那封信，点「去看看」→ 应收到「演示结束：你选择了 go」；
4. 看调试窗顶部：**动作总数 42**、"本次可见"显示当前分组与数量；
5. 目标到期/每日提醒：演示里设了 3 天，第二天起每天一条消息，到期一条"目标到期"。

如果第 2 步失败，调试窗的「剧情运行时」会直接写出是哪个动作、什么原因
（校验失败整段不执行，不会留下半截副作用）。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 无法离线跑真实游戏 | 本轮只做了编译验证 + 纯逻辑审查；UI/镜头/信件栏需要你在游戏里看一眼 |
| 音效 | 见 §2：1.7 没有公开播放入口 |
| 常驻 HUD | 见 §2：AlertsReadout 无注册入口，目标是"信件 + 每日消息" |
| 世界层 | B4 整批未做（`world.site` / `faction.hostility` / `world.caravan`） |
| 玩家点地图 / 点人 | `pick_cell` / `pick_pawn` 按你的要求不做 |
| `map.building` 的多格建筑 | 3×3 以上的建筑可能因空间不足生成失败（会记日志，不中断其它动作） |
