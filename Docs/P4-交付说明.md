## 3. 顺手修掉的一个老 bug

旧版本里，**同一阶段"先生成、后引用"是必定失败的**：

`~lua
actions[#actions+1] = { opId="a1", type="pawn.spawn", args={ pawnKind="Villager", handle="p1" } }
actions[#actions+1] = { opId="a2", type="pawn.hurt",  args={ handle="p1", hediffDef="Cut" } }  -- 旧版必被拒
`~

原因：`ValidateAll` 在**执行之前**跑，此时句柄还没登记。动作库参考里的示例其实一直是错的。

现在：校验阶段把"本阶段 spawn 类动作声明要生成的句柄"当作 pending 放行，
执行阶段严格解析（`ActionContext.Validating` 控制）。如果脚本把引用写在生成之前，
执行到时仍然解析失败——但那属于脚本顺序错误，不是校验器的问题。

## 9. 0.6.1 修正（2026-11-18）

你指出两个问题，都成立，已修：

### 9.1 危险动作被硬编码成「永远不能指向殖民者」

- 旧：`TargetPolicy.HandleOnly` 在 `WhoResolver` 里直接拒绝任何非 `handle:` 的目标，
  设置里那个「允许心理层」开关只影响想法/心情，对伤害/击杀/崩溃完全无效——等于「选项」只做了一半。
- 新：删除这条硬编码，改成 **三档设置**（设置 → 动作库 → AI 对你的殖民者的影响）：
  - **不允许**：只影响 AI 生成的角色；
  - **仅心理层**：+ 想法 / 心情 / 关系 / 特质 / 技能；
  - **全部（默认）**：+ 伤害 / 击杀 / 精神崩溃。
- 校验器按档位放行；档位不够时错误信息会直接写「请把设置改成 X」。
- 危险预算不变：每次事件最多 3 次危险动作。

### 9.2 信件抉择「点开没有选项」

- 旧：`NarrativeChoiceLetter` 继承原版 `ChoiceLetter`，靠基类的 `Choices` 面板渲染。
  那条路径依赖内部的 `DiaNode` 构造，1.7 上不可控（会出现点开信、没有任何按钮）。
- 新：重写 `OpenLetter()`，点开信直接用我们自己的 `Dialog_NarrativeChoice` 列出选项，
  选中后移除信件并把 `choice_selected` 投回事件。**选项一定在，不再依赖原版面板。**

### 9.3 设置入口的位置

- 「动作库」一节从设置页最下面（Def 查询之后）移到 **事件配额之后、叙事风格提示词之前**，不用滚到底找。
### 9.4 怎么自己验一下（30 秒）

1. 设置 → 动作库：确认第一行是「AI 对你的殖民者的影响：全部」；
2. 调试窗 →「强制写 Lua 剧情」，概念随便写一句，然后看它敢不敢用 `who="colonist:名字"`；
3. 想直接验证，手写一段脚本（调试窗的注入只认内置示例，最快是用模型/或改示例）：

```lua
function run(ctx, state)
  local actions = {}
  local s = state
  if ctx.trigger == "start" then
    actions[#actions+1] = { opId = "a1", type = "pawn.hurt",
      args = { who = "worst:Mood", hediffDef = "Cut", severity = 0.1 } }
    actions[#actions+1] = { opId = "a2", type = "story.send_letter",
      args = { title = "测试", text = "如果收到这封信，说明危险动作已经能落到殖民者身上。" } }
    return rim.aist.json_encode({ actions = actions, next_state = s, done = true })
  end
  return rim.aist.json_encode({ actions = actions, next_state = s })
end
```

把设置改成「仅心理层」再跑一次：应当在调试窗看到「玩家把…设成了「仅心理层」…」的拒绝原因。

## 10. 0.6.2 修正：Def 名字写错导致整段被拒（2026-11-18）

### 10.1 现象与根因（来自 Player.log，非猜测）

你这次测试的日志里，两次拒绝分别是：

```text
script preview failed: start 分支空跑失败：第 2 条动作（opId="s1_hurt"） pawn.hurt 校验失败：不存在的 HediffDef：Fracture
script rejected permanently: choice_selected 分支（choice="reset"）空跑失败：第 2 条动作（opId="d2_infect"） pawn.hurt 校验失败：不存在的 HediffDef：Infection
```

也就是说：**脚本本身结构没问题，是模型编了两个不存在的 HediffDef 名字**。

- `Fracture`：这个版本（1.7）根本没有骨折类 HediffDef（我查了所有 XML 与 Assembly-CSharp）；
- `Infection`：真实名字是 `WoundInfection`（还有 `ScariaInfection`）。

旧行为是 handler 抛一句「不存在的 HediffDef：X」→ 整段作废；重试时模型拿到的也只有这句话，
于是换了个同样不存在的名字再撞一次。

### 10.2 改了什么

1. **近义自动纠正**（`DefArgResolver`，在所有动作校验之前）：
   精确名字不存在时，先按 defName / 标签找唯一相近项，`Infection` → `WoundInfection`，
   命中就替换并写一行 `def near-miss` 日志；只有唯一命中才替换。
2. **报错直接给可用名字**：真的找不到时（如 `Fracture`），错误会列出该类别里最短的几个真实名字，
   并提示可以写 `@hediff/关键词`。重试时模型拿到的是「有哪些名字」，不再是一句「不存在」。
3. **动作手册补例子**：`pawn.hurt` / `pawn.heal` 的 hediffDef 现在直接写常用值
   （`Cut` / `Bruise` / `Gunshot` / `WoundInfection`），降低第一次就编名字的概率。

### 10.3 怎么确认修好了

- 让模型再写一次含 `pawn.hurt` 的脚本；若它写 `Infection`，日志里应出现
  `def near-miss hediffDef: "Infection" -> WoundInfection`，脚本正常执行；
- 若它写 `Fracture`，仍会被拒，但 `LastStatus` 里会列出可用名字，重试一次基本能改对；
- 想完全不撞名字：让脚本写 `@hediff/感染`。

## 11. 0.6.3：外伤没有部位（以及同类问题）（2026-11-18）

### 11.1 现象

`pawn.hurt` 加 `Cut` 时，健康面板显示 **"(no body part)"**，并伴随游戏报错。

根因：执行时调用的是 `HediffMaker.MakeHediff(def, pawn)`（不传部位）。
外伤类 Hediff（`Hediff_Injury`：Cut / Bruise / Gunshot / Stab / Bite…）**必须有 BodyPartRecord**：
疼痛、流血、治疗、渲染都从 `hediff.Part` 取数据，空部位会在这些路径里踩空引用。

### 11.2 修法

- `pawn.hurt` 新增 `part` 参数；不写时自动从 `GetNotMissingParts()` 里挑一个，
  优先避开脑 / 心 / 肝 / 肺（`ConsciousnessSource` 等 tag），显式写 `part="Brain"` 仍然可以；
- `part` 支持 defName（`Leg`）与本地化标签（`左腿`）；解析不到会列出可用部位；
- `pawn.heal` 支持 `part` 过滤，并且同一状态在多处时会**全部移除**（旧存档里的坏伤也能清掉）；
- 结构类状态（缺肢 / 假肢 / 植入物）现在会被拒绝——它们不是"受伤"，走 `pawn.hurt` 只会造出更坏的存档；
- 可包扎的伤口类状态（如 `WoundInfection`）也会自动绑定部位；流感/瘟疫这类全身疾病保持 whole-body。

### 11.3 同一类"参数合法但游戏状态非法"的地方，一并修了

| 动作 | 原来的问题 | 现在的行为 |
|---|---|---|
| `thing.spawn` / `story.reward` / `map.drop_pod` | 对 "需要材质" 的 ThingDef（墙、家具）直接 `MakeThing` 会抛异常 | 校验阶段直接拒，并提示换成品定义或用 `map.building` |
| `map.building` | 多格建筑直接 `GenSpawn`，压到墙/水/别人身上抛异常（预算已扣、前面的已落地） | 先检查整块占地（边界、已有建筑、地形支撑），找不到空地就报错 |
| `map.corpse` | 在墙/水里生成角色会抛异常 | 先挪到最近可站立格，再 try/catch |
| `pawn.spawn` / `map.animal` | 生成/落地异常会把整阶段打崩 | try/catch + 明确错误；猎杀状态失败只记警告，不再作废整段 |
| `map.plant` | 可以在水里/建筑格上种植物 | 检查地形肥力与占用 |
| `pawn.gear` | 不检查身体部位是否够穿、也不检查是不是真武器 | `HasPartsToWear`、衣物/武器类型检查、穿戴/装备 try/catch |
| `pawn.set_skill` | 对没有技能系统的角色直接取技能 | 先检查 `skills` 与技能是否可用 |
| `pawn.join` | 不检查是否真的加入了 | 执行后校验派系，失败返回错误 |
| `research.grant` | 已完成的项目仍可加进度 | 直接拒绝已完成项目 |
| `pawn.inspiration` | `TryStartInspiration` 失败也当成功 | 失败返回可读错误 |
| `story.choice_letter` | 直接 new 的 Letter ID = 0，归档/去重会撞 | 分配 `GetNextLetterID()` |

> 旧存档里已经有 "(no body part)" 的伤：用 `pawn.heal{who="colonist:名字", hediffDef="Cut"}` 清掉即可（现在会移除该状态的所有实例）。

## 12. 0.6.4：severity 的语义被写错了（2026-11-18）

### 12.1 问题

`pawn.hurt` 以前对所有状态都用同一个 `severity 0.1~0.8`，但游戏里这是两套完全不同的量：

| 类型 | Severity 的含义 | 实际范围 |
|---|---|---|
| 疾病（Flu / Plague / WoundInfection…） | 0..1 的病程，到 `lethalSeverity`（多为 1）死亡 | 0 ~ 1 |
| 外伤（Cut / Bruise / Gunshot…） | **伤害点数** | 1 ~ 部位血量（躯干 40、头 20、四肢 30） |

所以 0.1~0.8 这个夹取：对外伤只能造出「擦破皮」，对疾病又接近致死——两边都不对。

### 12.2 改法

- 外伤用 **`damage`**：1 ~ 部位血量，可以直接写 `damage=40` 打躯干；
- 疾病用 **`severity`**：0.05 ~ 0.95；写 1（= 死亡）会被拒绝并提示改用 `pawn.kill`；
- 外伤仍接受旧写法 `severity`，但语义改成「部位血量的比例」（0.5 = 半管血）——
  0.6.3 之前写的 `severity=0.8` 现在是一道重伤，而不是 0.8 点伤害；
- 实际落地留 5%：最多打到部位血量的 95%，不会把部位变成「缺失」；要彻底毁掉部位请用 `pawn.kill` / `map.damage`；
- 给疾病写 `damage`、给外伤写超范围的 `severity`，都会在**校验阶段**被拒并说明该用哪个参数。

### 12.3 例子

```lua
-- 躯干挨了一刀，8 点伤害（需要包扎，不致命）
{ type = "pawn.hurt", args = { who = "colonist:米娅", hediffDef = "Cut", part = "Torso", damage = 8 } }

-- 几乎摧毁躯干：38 / 40 点（不会真的把躯干打成缺失）
{ type = "pawn.hurt", args = { who = "colonist:米娅", hediffDef = "Cut", part = "Torso", damage = 38 } }

-- 感染：病程 0.6（到 1 才死）
{ type = "pawn.hurt", args = { who = "colonist:米娅", hediffDef = "WoundInfection", severity = 0.6 } }
```
