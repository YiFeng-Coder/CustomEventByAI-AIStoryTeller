# 本地化（Localization）

模组同时提供**英文**与**简体中文**，并且**英文是默认文本**：

- Def 名称与简介、`About/About.xml` 直接写英文（英文玩家看到的默认内容）；
- 中文放在 `Languages/ChineseSimplified/` 下，游戏语言是中文时自动覆盖；
- 其它语言（含未来的第三方翻译）缺条目时，RimWorld 会回退到英文。

游戏语言为中文 → 界面、信件、提示、**以及模型生成的剧情**都是中文；
其它语言 → 全部英文。叙事语言跟着游戏语言走，不需要单独设置。

## 目录结构

```
Languages/
  English/
    Keyed/AINarrator_Settings.xml        设置页
    Keyed/AINarrator_UI.xml              调试窗、抉择弹窗
  ChineseSimplified/
    Keyed/AINarrator_Settings.xml        与英文键一一对应
    Keyed/AINarrator_UI.xml
    DefInjected/StorytellerDef/Stellaris_AINarrator.xml   叙述者的中文名与简介
```

`Keyed` 里的键在两个语言文件中**必须完全一致**（键集合、`{0}` 占位符都一致），
否则某一语言会显示键名。改完用 `tools/check_loc.py` 与 `tools/check_cjk.py` 自检（见文末）。

## 两层文本，为什么

| 层 | 位置 | 适合什么 |
|---|---|---|
| 玩家可见文本 | `Languages/*/Keyed/*.xml` + `DefInjected/` | 设置页、调试窗、弹窗、Def 字段。翻译者不用改代码、不用重编译。 |
| 模型可见文本 | 代码里的 `Loc.Pick(中文, English)` | 提示词、动作手册、校验报错。动辄上万字、带缩进与代码块，塞进 XML 既难维护也难校对；而且校验报错必须和校验逻辑写在一起才不会漂移。 |

运行时玩家可见的**动态消息**（信件兜底标题、事件失败原因、配额提示等）也走 `Loc.Pick`：
它们大多由运行时拼接而成、带动态参数，逐条建键的维护成本高于收益。

## 代码里怎么用

```csharp
// 玩家可见、静态：走 Keyed
listing.Label(Loc.T("AI_Settings_ResetDefaults"));
listing.Label(Loc.T("AI_Settings_Temperature", value));   // {0}

// 模型可见 / 运行时动态：双语并列
error = Loc.Pick("text 不能为空", "text must not be empty");
```

- `Loc.T` 只接受同时存在于 `English` 与 `ChineseSimplified` 的键。
- `Loc.Pick` 的两个参数必须**语义等价**：中文那份同时是中文玩家的实际输出，
  改英文时不要顺手改中文，反之亦然。
- 不要用 `Loc.Pick` 包注释、`Verse.Log.*` 诊断日志、opId、JSON 键、DefName、存档字段名。

## 新增一种语言

1. 复制 `Languages/English/Keyed/*.xml` 到 `Languages/<你的语言>/Keyed/`，逐条翻译；
2. 如需翻 Def 字段，加 `DefInjected/StorytellerDef/Stellaris_AINarrator.xml`；
3. 在 `Docs/` 里记一笔。代码无需改动——`Loc.IsChinese` 只决定用中文还是英文，
   第三种语言若希望模型也跟着本地化，需要在 `Loc` 里扩展语言判定与提示词分支。

## 自检

仓库里有两个脚本（不参与构建）：

```powershell
python tools/check_loc.py     # 键集合 / 占位符 / Loc.Pick 参数完整性
python tools/check_cjk.py     # 是否还有漏包 Loc.Pick 的中文字面量（排除注释与 Log）
```

两者都应该输出 0 个问题。
