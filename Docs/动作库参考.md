# 动作库参考（42 个）

版本 0.6.4。这是 Lua 脚本能调用的全部动作；表里的上限就是校验器里的上限，
越界会导致**整段脚本**被拒（不是只跳过那一条）。

权限列：`叙事` 无副作用或仅 UI；`生成` 有界生成；`重大` 会伤人或改变世界，受危险/编辑预算约束。

---

## 0. 两个新写法（0.6.0）

### 位置：用 spot，不要猜坐标

以前所有位置都是绝对坐标 `{x,y,z}`，模型不知道地图多大，猜错就整段作废。
现在写语义锚点，由 C# 翻译成真实格（老写法 `cell={x,y,z}` 仍然可用）：

| 锚点 | 含义 |
|---|---|
| `center` / `colony_center` / `base` | 基地中心 |
| `storage` | 仓储区里随机一格（没有仓储区会报错） |
| `water` | 中心 40 格内最近的水面 |
| `ore` | 地图上随机一处可开采的矿 |
| `edge_north` / `edge_south` / `edge_east` / `edge_west` | 某一侧地图边缘 |
| `random` | 基地附近随机一格 |
| `handle:名字` | 某个句柄当前所在的位置 |

可加 `offset={x=0,y=0}` 做相对偏移，或 `jitter=0..12` 随机散开（用于"一片"而不是"一点"）。
锚点解析失败**会报错**，不会静默落到别的格子。

### 目标：用 who

角色类动作不再只能指向"本事件生成的角色"：

| 写法 | 含义 |
|---|---|
| `handle:p1` | 本事件自己生成的角色（老写法，兼容） |
| `colonist:米娅` | 你的殖民者（按名字） |
| `best:Shooting` | 某技能最高的殖民者 |
| `worst:Mood` | 心情最差的殖民者 |

**能不能落到你的殖民者身上，由「设置 → 动作库 → AI 对你的殖民者的影响」决定**（校验器里执行）：

| 设置 | 你的殖民者会受什么影响 |
|---|---|
| 不允许 | 只有正向动作（治疗 / 灵感）可用 |
| 仅心理层 | + 想法 / 心情 / 关系 / 特质 / 技能 |
| **全部（默认）** | + 伤害 / 击杀 / 精神崩溃（仍受每次事件 3 次的危险预算） |

- 危险动作（`pawn.hurt` / `pawn.kill` / `pawn.mental`）在「全部」下可以写
  `who=colonist:名字` / `best:技能名` / `worst:Mood`；
- 设置不够时动作会在校验阶段被拒，错误信息会直接告诉你该改成哪一档；
- 正向动作（`pawn.heal` / `pawn.inspiration`）在任何档位都可以指向你的殖民者。

### Def 名字写错会怎样（0.6.2）

1. **精确名字**：直接用；
2. **像但不是**（`Infection`、`wound infection`、`伤口感染`）：先按 defName / 标签找**唯一**相近项，
   命中就自动替换（`Infection` → `WoundInfection`），并在日志里写一行 `def near-miss`；
3. **找不到**（例如 `Fracture` —— 这个版本根本没有骨折状态）：整段脚本被拒，但错误里会直接列出
   可用的真实名字，并提示可以写 `@hediff/关键词`。

> 还是那句话：Def 参数可以写精确名，也可以写 `@类别/关键词`（如 `@hediff/感染`），
> 后者由游戏按 defName / 标签 / 描述搜索，最稳。

### 身体部位（0.6.3）

`pawn.hurt` 的外伤类状态（`Cut` / `Bruise` / `Gunshot` 等）**必须落在具体部位**上。
以前不传部位，会生成 "(no body part)" 的伤：健康面板显示异常，治疗/疼痛/流血计算会踩空引用。

- 不写 `part`：自动从未缺失的部位里挑一个，优先避开脑/心/肝/肺这类一击致命的器官；
- 写 `part="Leg"`：按 BodyPartDef 名字挑（左右腿会随机一侧）；
- 写 `part="左腿"`：按本地化标签挑；
- 写 `part="Brain"`：也可以，后果自负。

> 旧存档里已经存在的 "(no body part)" 伤，用 `pawn.heal{who=..., hediffDef="Cut"}` 就能清掉。
>
> 另外：`MissingBodyPart` / 假肢 / 植入物这类结构类状态不能通过 `pawn.hurt` 施加（会直接拒绝）；
> `WoundInfection` 这类可包扎的伤口会像外伤一样自动绑定部位。

### severity 与 damage：两套语义（0.6.4）

这里以前只有一个 `severity 0.1~0.8`，是错的——外伤和疾病的 Severity 根本不是一回事：

| 状态类型 | 用哪个参数 | 范围 | 含义 |
|---|---|---|---|
| 外伤（Cut / Bruise / Gunshot / Stab…） | `damage` | 1 ~ 部位血量 | 伤害点数；`Hediff_Injury.Severity` 就是它，**可以远超 1** |
| 外伤（旧写法） | `severity` | 0.05 ~ 1 | 按「部位血量的比例」折算（0.5 = 半管血） |
| 疾病（Flu / Plague / WoundInfection…） | `severity` | 0.05 ~ 0.95 | 0..1 的病程；到 `lethalSeverity`（多为 1）就死亡 |

部位血量举例：躯干 40 点、头 20 点、四肢 30 点（以实际 BodyPartDef 为准）。

- 写 `damage=40` 打在躯干上 = 几乎摧毁；写 `damage=8` = 一道需要包扎的伤口；
- 外伤的 `damage` 上限是部位血量；超过会直接报错并告诉你上限；
- 实际落地时会留 5%：**最多打到部位血量的 95%**，不会把部位变成「缺失」（那会走另一套逻辑）。
  要彻底毁掉部位，用 `pawn.kill` 或 `map.damage`；
- 疾病写 1 会被拒绝：那等于直接致死，请用 `pawn.kill`；
- 给疾病写 `damage`、给外伤写超范围的 `severity` 都会被拒，并说明该改用哪个。

## 句柄（handle）怎么用

Lua 里没有对象引用，所以"之后还要操作某个东西"必须先给它起名：

`~lua
if ctx.trigger == "start" then
  -- 生成一个角色，并登记成 p1
  actions[#actions+1] = { opId = "a1", type = "pawn.spawn",
    args = { pawnKind = "Villager", count = 1, handle = "p1" } }

  -- 同一阶段里紧接着用 p1（0.6.0 起可用：校验阶段把它当作"待生成"放行）
  actions[#actions+1] = { opId = "a2", type = "pawn.hurt",
    args = { who = "handle:p1", hediffDef = "Cut", severity = 0.4 } }
end
`~

- 句柄随事件实例存档，**读档后依然能解析**；
- 解析失败（对象被摧毁 / 确实没生成）→ 该动作校验失败 → 整阶段作废；
- 每个实例最多记 32 个句柄。

## 提示词里只显示"这次用得上"的动作组

动作库有 42 个，但一次编剧请求不会把 42 行手册全塞进去（会顶到 10k 字）：

- 常驻：叙事 + 生成 + 地图 + 角色（23 个）；
- 按剧情关键词出现：心理 / 场景 / 交互 / 世界，最多再加两组；
- 玩家在设置里关掉的组一律不出现。

**裁剪只影响"提示词里看不看得到"，不影响能不能执行**——运行时白名单始终是全部 42 个，
所以模型写出没展示的动作照样能跑。调试窗顶部的"本次可见"会显示这次给了几组。
